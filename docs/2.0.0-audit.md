The mockup draws these by hand. The real build uses the SF Symbols above, plus
new ones for pip, npm and editor extensions (pick when building: `shippingbox`
is taken, so check SF Symbols for a Python/Node-style glyph or a custom symbol).

**Old logo.** The UpdateScout icon is a blue to violet backdrop with a green
disc, a white download arrow and a white update ring (layered SVGs in
`Resources/Icon/`, regenerated by `generate.py`). `AppLogo` in `Style.swift`
draws the running app's own icon in the window header and Settings. The new
Prism Layers icon keeps the blue-violet backdrop so it reads as the same app.
`UpdateScout.icon` and `UpdateScout New.icon` at the repo root are older
experiments and are not used by the build (`build-app.sh` compiles
`Resources/AppIcon.icon`). Leave them, or delete once 2.0 ships.

## What the Glass slider changes (1.8.0)

`GlassBackground` draws the window as a real Liquid Glass effect, then lays a
light or dark wash over it at `slider x 0.9` opacity.

- Slider at **Clear (0)**: the pure system glass, the most see-through. The
  desktop and windows behind show through.
- Slider at **Opaque (1)**: a 90% wash, so the window reads nearly solid.
- It changes **only the window background**. Section panels and cards use
  `Theme.card` (fixed 55% opacity) and a fixed 20% section tint, so they do not
  get glassier or less glassy with the slider.
- On macOS 27 the system now has its own glass slider. Recommendation stays:
  follow the system setting on 27 and keep this slider for 26.

## How Discover gets its data

| Source | Endpoint | Size / cost | Notes |
|---|---|---|---|
| Homebrew casks | `formulae.brew.sh/api/cask.json` | 2.1 MB over the wire, 19 MB decoded | **Already downloaded daily** for the cask oracle (`cask-index.json`). Reuse it. |
| Homebrew formulae | `formulae.brew.sh/api/formula.json` | 5.2 MB over the wire | New. Daily at most. |
| Popularity | `formulae.brew.sh/api/analytics/cask-install/30d.json`, `.../install/30d.json` | 0.2 and 0.3 MB | Drives "Popular this week". |
| npm | `registry.npmjs.org/-/v1/search?text=` | live, small | Works unauthenticated. |
| crates.io | `crates.io/api/v1/crates?q=` | live, small | Needs a User-Agent header. |
| RubyGems | `rubygems.org/api/v1/search.json?query=` | live, small | Works unauthenticated. |
| PyPI | JSON API by exact name only | n/a | No search endpoint I could confirm. Search PyPI by exact name, or ship a bundled list of popular packages. |
| Editor extensions | marketplace APIs | unchecked | Verify before promising it. |

Pattern: bulk lists (Homebrew) are cached on disk and searched locally, so
typing feels instant and works offline. Per-ecosystem registries (npm, crates,
gems) are queried live as the user types, debounced, with results cached for
the session. Nothing is fetched until the Discover tab is first opened, and a
failed source shows its own error line without blocking the others.

## How heavy the app is (measured on this Mac)

| Measure | 1.8.0 today |
|---|---|
| App bundle | 7.9 MB (binary 2.8, Sparkle 3.0, resources 2.1) |
| Download (zip) | 3.9 MB |
| Memory, running 11 hours in the menu bar | 30 MB resident |
| CPU while idle | 0.1% |
| Data on disk | about 19.4 MB (almost all `cask-index.json`) |

Expected for 2.0:
- **App size:** about 10 to 12 MB. New code and a few new assets. No new frameworks needed.
- **Disk:** about 35 MB with the formula list cached too (the decoded cask file is 19 MB, formulae will be larger).
- **Memory:** the daily index parse is the main risk. Parsing 19 MB of JSON into
  Swift objects can briefly spike to a few hundred MB, then it falls back.
  Fix: parse once into a compact searchable index, on a background task, drop
  the raw JSON straight away, and keep only names, descriptions and versions.
  Target: under 80 MB resident with Discover open, under 40 MB idle.
- **CPU and network:** checks stay the same. Discover adds at most two downloads
  a day (about 7 MB) and only after the tab is opened.
