# Adoption: moving self-managed apps onto Homebrew

Written 29 Oct 2026. Part of the 2.0 build. Shown in the mockup as the teal
banner on Updates, the review sheet, the Installed badges, and a Settings group.

**What it is.** Some apps were downloaded by hand and nothing keeps them up to
date, yet Homebrew has a cask for them. PrismPack spots these and offers to move
them under Homebrew, so they get updated with everything else. It never does
this without asking.

## What is already true in 1.8.0

- `CaskOracleSource` already matches apps in `/Applications` and
  `~/Applications` to Homebrew casks by app filename or display name. It skips
  apps Homebrew already manages and skips Mac App Store apps.
- It only acts when the cask's version is **newer** than the installed one, and
  it installs with `brew install --cask <token> --force`. So today an app is
  only "adopted" as a side effect of an update, never offered while up to date.
- The caveat text already warns "this app will become Homebrew-managed".

2.0 adds: offering adoption on its own, a much stricter match, a verified
procedure, and an undo.

## What I checked about Homebrew (7.0.11 on this Mac, and the cask list)

- `brew install --cask --adopt` adopts existing artifacts "that are identical to
  those being installed". Identical means **the installed app must be the same
  build as the cask's current download**. An older installed version cannot be
  adopted. It cannot be combined with `--force`.
- Of 7,814 casks, 4,206 install an `app`. **656 use a `pkg` installer.** A pkg
  cask has no app to adopt: it installs by running an installer.
- **2,050 casks are marked `auto_updates`**, meaning the app updates itself.
- **Microsoft Word is a pkg cask and also auto-updates** (via Microsoft
  AutoUpdate). So it cannot be adopted in place. Moving it means running the
  installer again, which needs the admin password. It is a poor first example
  of "adoptable", and the mockup shows it that way on purpose.
- **Tested 30 Oct 2026 (Phase 7) on Itsycal and Low Profile:**
  - `--force` over an existing app prints "overwriting" and **removes** the old
    app (not to the Trash). The design never uses it.
  - `--adopt` **downloads the cask's file** to compare (1.8 MB for Itsycal).
  - `--adopt` **accepted an older copy** (0.27.2 for a 0.27.3 cask) and recorded
    it as 0.27.3, so `brew outdated` stayed silent. Homebrew's "identical" isn't
    enforced: PrismPack checks the exact version itself, before and after.
  - Removing `Caskroom/<token>` makes Homebrew forget the app and leaves the app
    untouched. For an app cask it holds only metadata and a link; for a pkg cask
    it also holds the downloaded installer.
  - A pkg cask installs its app owned by root, so undoing a Replace needs admin
    rights, and the installer's receipt (`pkgutil --forget`) goes too.

## Two ways to move an app, chosen automatically

| | **Adopt in place** | **Replace** |
|---|---|---|
| When | Cask has an `app` artifact, **and** the installed version equals the cask version | Installed version is older, or the cask is a pkg |
| Command | `brew install --cask --adopt <token>` | Move the old app to the Trash, then `brew install --cask <token>` |
| Downloads | The cask's download, once, to compare | The cask's download |
| Admin password | No | Sometimes (pkg) |
| Risk | Very low, because PrismPack checks the version itself (Homebrew doesn't) | Low, because the old app is in the Trash until the new one is verified |
| Undo | Move the cask's Caskroom folder to the Trash (metadata only) | Put the old app back from the Trash, remove the cask record (and, for a pkg, the installer receipt, with the password) |

PrismPack never uses `--force` for this. The app goes to the Trash first, so a
failed install can always be rolled back.

## Is Homebrew actually better for this app? (the decision logic)

Being adoptable does not mean it is a good idea. A cask can lag behind the
vendor's own releases, an app's own updater may send small delta updates where
Homebrew re-downloads the whole app, and some apps update themselves silently.
So every candidate gets a **verdict**, and only a good verdict is shown by default.

**The baseline is what the app does today.**

| Today | What Homebrew can add | Default |
|---|---|---|
| **No updater at all** (nothing finds new versions) | Everything: it gets updates at all | Suggest, if the cask is current |
| **Has its own updater** (Sparkle, Squirrel, `auto_updates`) | Only a single place to update, and maybe a quicker rollout | Do **not** suggest. Shown only with "Include apps that already update themselves", and only with the comparison below |

**Facts compared (only facts we can read, never a guess):**

| Fact | Where it comes from | Rule |
|---|---|---|
| **Freshness.** Is the cask as new as the vendor's release? | Cask version vs the app's Sparkle feed, when it has one (PrismPack already parses these) | If the cask is **older** than the vendor's latest: verdict **Not better**. Homebrew would hold you back. |
| **Download size** | `Content-Length` from a HEAD request to the cask's URL, fetched only when the sheet opens and cached. For Sparkle apps, the appcast's `length`, and whether it lists **delta** updates. | If the vendor ships deltas and the cask is a full download, say so. It is a **cost**, not a blocker. If the size can't be read, show "size unknown" and **do not** use it in the verdict. |
| **Needs admin** | Cask has a `pkg` artifact | A cost: needs a password on every update, not just the move. |
| **Self-updating** | Cask `auto_updates`, or an updater found in the bundle | Reason to skip (see above). |
| **Channel** | The installed version is a beta, but the cask tracks stable | **Not better**: Homebrew would offer a downgrade. |
| **Architecture or minimum macOS** | Cask's `depends_on` and the app's own `LSMinimumSystemVersion` | If the cask can't run here: hidden. |
| **Cask health** | Deprecated, disabled, `latest`, wrong tap | Hidden. |

**Verdicts shown to the user**

- **Recommended:** no updater today, the cask is current, in-place adoption is possible, no admin.
- **Worth considering:** no updater today, but it costs something (needs a password, or Replace is needed, or a big download). The cost is shown in plain words.
- **Not better:** the cask lags, or it is a beta, or the app already updates itself and nothing is gained. Hidden by default. If shown, the reason is the first line.

**No claims without data.** The sheet never says "faster" or "smaller" unless
both numbers were actually read. A missing number shows as "unknown", never a
guess. The decision uses only the freshness, channel, updater and compatibility
facts above, which are all readable offline or from files PrismPack already
fetches. Sizes are shown for information.

**It can change over time.** If a cask falls behind the vendor later, an
adopted app shows a small "Homebrew is behind the vendor's release" note on its
card, with the option to open the vendor's page or stop managing it.

## What makes it airtight

### 1. A candidate must pass every check

1. **Strong match, not just a name.** Cask matches by app filename **and** at
   least one of: bundle identifier (from the cask's `uninstall` quit ids when
   present), or the same version string as the cask. Name alone is never enough.
2. **Not already Homebrew-managed.** `brew list --cask` succeeded and does not
   contain the token. If that command fails, **stop and offer nothing**, as
   1.8.0 already does.
3. **Not a Mac App Store app.** No `_MASReceipt`. Not an iPhone or iPad app.
4. **Not a system app,** and not inside another app's bundle.
5. **Exactly one copy** of that app on disk. Two copies (`/Applications` and
   `~/Applications`) means skip.
6. **Cask is healthy.** Not deprecated, not disabled, version is not `latest`,
   and it comes from the official `homebrew/cask` tap.
7. **No other updater** found by default (this is the baseline in the decision logic above): no Sparkle feed key, no
   `Sparkle.framework`, no Squirrel or Electron updater, no Microsoft
   AutoUpdate or Google Keystone, and the cask is not marked `auto_updates`.
   Apps that already update themselves are listed only if the user turns on
   "Include apps that already update themselves". This keeps the suggestions
   to apps that genuinely have no updater.
8. **Homebrew is installed.** If not, offer to set it up (the existing Setup
   flow) instead of adopting.

Every check is recorded, and the review sheet shows them as ticks so the user
sees why the app was suggested.

### 2. Nothing changes without a click

- Detection only **reads**. It may run in the background check, where it only
  writes the candidate list. Adoption itself **never** runs headless.
- The sheet shows the exact method, whether it downloads, and whether it needs
  a password. One click per app, or "Adopt all that are safe", which only
  includes in-place adoptions.

### 3. Verified after, undone if wrong

After adopting or replacing:

- `brew list --cask <token>` lists it, and the app is at the same path.
- Its bundle identifier matches what it was before.
- For Replace: it launches (`open -g`, then check the process), and the version
  is the cask's.

If any check fails: **Adopt in place** has changed nothing on disk, so just
report. **Replace** puts the old app back from the Trash and removes the cask
record. The failure is shown with a Retry.

### 4. Undo later: "Stop managing with Homebrew"

Removes only the cask's Caskroom folder, after confirming it contains nothing but
metadata. It **never runs `brew uninstall`**, which would delete the app. It
asks before doing it.

### 5. Safe with the rest of the app

- **Item IDs do not change.** Adoption candidates live in their own list,
  separate from update items, so ignored and notified lists survive. Per
  [CLAUDE.md](../CLAUDE.md), changing the ID format would reset them.
- All writes go through `Store.mutate`, as always.
- Adoptions run in the Homebrew lane, one at a time, because Homebrew locks.
- Arguments are passed as an array, never a shell string, and the cask token is
  checked against `^[a-z0-9@+._-]+$` and against the cask list before use.
- Offline or cask list stale: no suggestions, no errors shown.

### 6. Not annoying

- One digest notification at most, never one per app, and at most once a week.
- **Not now** hides an app for 30 days. **Never for this app** hides it
  permanently. Both appear in the Hidden section, with Bring back.
- A single master switch in Settings, and a second for apps that update
  themselves.

## Test cases before shipping

0. Cask older than the vendor's Sparkle release: **not** offered, or shown as Not better.
0. Installed beta, cask is stable: Not better, no downgrade offered.
0. HEAD request for the size fails: sheet shows "size unknown", verdict unchanged.
1. App with an `app` cask, same version, no updater: offered, adopts in place, nothing downloaded.
2. Same app, older version: offered as Replace, old app visible in the Trash until verified.
3. pkg cask (Microsoft Word): offered as Replace, password prompt, app launches after.
4. App Store app with a cask of the same name: never offered.
5. Two copies on disk: never offered.
6. Same filename, different bundle ID: never offered.
7. `brew list --cask` fails: nothing offered, no error spam.
8. Replace where the install fails: old app restored, cask record removed.
9. Stop managing: app untouched, Caskroom folder gone, app returns to the list.
10. Adopt run twice, or while an update batch is running: second run waits for the Homebrew lane.
11. Background check: candidates found, no adoption, one digest notification.
12. Ignored items from 1.8.0 are still ignored after the upgrade.
