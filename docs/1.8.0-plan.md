# UpdateScout 1.8.0

Branch: `release/1.8.0`. Built locally for testing only. Nothing is pushed,
tagged, or added to `appcast.xml` until it has been tried by hand.

## A. Badge and state accuracy

- **Live menu bar count.** The app used to re-read `state.json` only when the
  popover or window opened, so results from the background agent never reached
  the badge. Now the app also reloads:
  - when `state.json` changes on disk (file watcher),
  - on wake from sleep and when the app becomes active,
  - on a 5-minute fallback timer.
- **Checking indicator.** The menu bar icon shows a "…" while a check runs, so a
  stale number never looks final.
- **`state.json` overwrite race.** The app and the background agent each wrote
  the whole file from their own copy, so the app could erase newer agent
  results (and the "already notified" list). Every write now re-reads the file
  and applies only the change being made.
- **Post-install re-check.** If a check was already running when the install
  queue drained, the follow-up check was dropped and updated apps could
  reappear. It is now queued and runs when the current check finishes.

## B. Safety

- **Leftover drivers.** If `kmutil` fails, every third-party kext used to be
  listed as "safe to remove". A failure now means "unknown": no leftovers are
  shown.
- **Removal confirmation.** Removing a leftover driver asks first.
- **Password prompt wording.** The prompt says what is happening (installing
  an update, replacing an app, removing a driver) instead of always "install an
  update".
- **Major-version review sheet.** Update All, a section's Update All, and the
  Update button on a single major-upgrade card open a review sheet:
  - one row per major upgrade with icon, version jump and an Include toggle
    (off by default),
  - expandable release notes per row, or a link to the vendor page,
  - an "I've reviewed these" checkbox; **Proceed** stays disabled until ticked,
  - **Skip these, update the rest** and **Cancel**,
  - Liquid Glass styling to match the main window.
- **Sparkle quit-wait.** If the app being updated will not quit within 10
  seconds (for example, it is showing an unsaved-changes dialog), the install
  stops with a message instead of replacing a running app.
- **Cancel during Sparkle downloads.** Cancel now stops the download, not only
  child processes.
- **Custom sources.** Installs used to look up the entry by its position in
  `custom_sources.json`, so editing the file between a check and an install
  could run a different entry's command. Entries are now matched by name, and
  the install refuses if the command changed since the check.

## C. Wrong or phantom updates

- **Release track detection (Sparkle).** The track is worked out from the
  installed version:
  - an installed prerelease (`-alpha`, `-beta`, `-rc`, or a build tagged with
    a channel in the feed) puts the app on that track,
  - stable sees stable only; beta sees beta and stable; alpha sees everything,
  - an item is treated as a prerelease if it has a `sparkle:channel` tag **or**
    a prerelease marker in its version (Thaw's feed leaves some betas untagged).
  - Example: Thaw 3.0.0-beta.4 is offered beta.5 and 3.0.0 final, never alpha
    builds.
- **Minimum macOS.** Feed items whose `sparkle:minimumSystemVersion` is newer
  than the running macOS are skipped.
- **Version comparison.**
  - A leading `v` is ignored (`v1.0` equals `1.0`).
  - A release ranks above its own prereleases (`3.0.0` > `3.0.0-beta.4`).
  - Prereleases order by stage then number (`alpha.10` < `beta.1` < `rc.1`).
- **Item IDs.** IDs now include the install token, so a formula and a cask with
  the same name no longer merge. This resets "ignored" and "notified" once.

## D. Reliability

- **Command output.** Output chunks from `brew`, `mas` and others are collected
  in order, and progress lines are split correctly across chunk boundaries.
- **Background agent.** The launchd reload waits for `bootout` to finish before
  `bootstrap`, runs off the main thread, and reports errors in Settings.
- **Release notes.** Notes are parsed once, not on every redraw. Markdown
  (GitHub notes) renders as Markdown.

## E. Small cleanups

- The cask oracle stops if `brew list` fails, instead of treating every cask as
  unmanaged.
- The GitHub notes cache is capped by dropping the oldest entries.
- Dead `softwareupdate -i` install path removed (macOS updates always open
  System Settings).

## Deferred to 2.0.0

- Choosing a channel per app (alpha / beta / stable), which needs a view of all
  installed apps, not just outdated ones.
- Parallel installs, single admin authorization, automatic updates.
- Browse and search (Discover tab).

## Testing the local build

1. Quit the installed UpdateScout (menu bar icon → power button). Both copies
   share `~/Library/Application Support/UpdateScout/`.
2. Build: `scripts/build-app.sh` (no `--install`). Output:
   `build/UpdateScout.app`.
3. Run: `open build/UpdateScout.app`.
4. Do not toggle "Check for updates in the background" in the test build: it
   would point your real launchd agent at the test copy.
5. When done, quit it and reopen `/Applications/UpdateScout.app`.

Things to try:
- Leave the window closed and run
  `"/Applications/UpdateScout.app/Contents/MacOS/UpdateScout" --background-check`
  in Terminal; the test build's badge should update within a few seconds.
- Update All with a major upgrade in the list: the review sheet appears.
- Thaw should not appear unless a newer beta or the 3.0.0 final is out.
