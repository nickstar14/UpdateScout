## 0. Rules of engagement (read twice)

### 0.1 Follow the plan. Do not veer.

**Build what this guide and the documents it links say. Nothing more, nothing
less, and not a different way, unless Nick asks.**

"Veering" means any of these without Nick's explicit OK in chat:

- adding a feature, source, screen, setting or option that isn't in the plan
- dropping, postponing or simplifying something that is in the plan
- changing a design, name, colour, layout or behaviour the plan has decided
- swapping an approach for one you prefer (a different architecture, library,
  file layout, data format, or way of doing the same job)
- "while I'm here" refactors, cleanups, renames or reformatting of code you
  don't need to touch
- adding dependencies, entitlements, background services or helper tools

**If you think the plan is wrong, unclear, impossible, or can be improved: stop
and ask Nick.** State the problem, what you found, and your suggestion, then
wait. You may suggest. You may not act on the suggestion until Nick says yes.
That includes small things. When in doubt, ask. Asking is cheap. Undoing is not.

**Not veering:** fixing a compile error in code you are writing, choosing a
variable name, and writing the glue code a step needs. Those are just
implementing the plan.

**If two documents disagree,** this guide wins. If this guide is silent or
unclear, ask. Don't guess.

## 1. Context

**UpdateScout** is a Swift (SwiftPM) macOS menu bar app, about 5,000 lines,
that finds updates from Homebrew, the Mac App Store (`mas`), Sparkle feeds,
macOS updates (`softwareupdate`), a Homebrew-data "cask oracle", drivers and
extensions, and custom shell sources, and installs them. Version **1.8.0**
(build 25) is released and installed on Nick's Mac.

**2.0 turns it into PrismPack:** a Mac-native cross between UniGetUI and
CaskHub, with everything 1.8.0 does already built in. Nick's requirements:

1. Simultaneous updates.
2. One password prompt for a whole batch.
3. Keep all of today's sections.
4. Many more categories of updatable things (pip, npm and more).
5. A search and store-style **Discover** tab across many categories, excluding
   the App Store and macOS system updates.
6. A new look that follows **macOS 27** and emphasises Liquid Glass.
7. A new name and icon.
8. A way to move apps that nothing updates onto Homebrew (**adoption**), done
   safely.

**The rule above all others: 2.0 adds to 1.8.0 and removes nothing.** The
checklist is in [2.0.0-parity-checklist.md](2.0.0-parity-checklist.md). Every
item there must still work when you are done.

**Machine facts:** macOS 27.2, Xcode SDK 27.0, Apple silicon, Swift 6.4. The
package builds in Swift 5 language mode (`.swiftLanguageMode(.v5)`), deployment
target macOS 15.

- **Name: PrismPack.**
- **Logo: "Prism Layers"**, three stacked glass prisms with a sheen and a glint.
  Nick builds the final icon in Icon Composer from the separate layers. **Do

  **"Update all <section>"** button.

  Discover, Installed, Activity, Settings. A sidebar collapse button.
- **Update at once** is a **Settings** option, not a toolbar control.
- **Password prompt** is a **popup sheet** that appears after a batch starts and
  only if something needs it. Not a bar at the bottom.
- **App icons on every row:** the app's real icon when it has one, else the
  first letter, else (for packages with no icon, like pip and npm) the
  **section's icon**.
- **Settings looks like today's Settings:** header with the logo, name,
  version and Check for Updates, then grouped cards. **Every source is listed**
  there with an on/off switch.
- **Icons match 1.8.0:** macOS uses the **Apple logo**, Settings uses a **gear**,
  Homebrew a mug. Use the SF Symbols 1.8.0 already uses (section 5.3).
- **Click an app's icon or name** to open a floating **detail card** with
  versions, a major-upgrade warning, release notes, Update, and **ignore
  options** (section 4.4).
- **Adoption** is a feature, with the strict rules in
  [2.0.0-adoption.md](2.0.0-adoption.md).
- **Discover** excludes App Store apps and macOS system updates.

### 3.3 Verified facts, and what is **not** verified

Verified:
- Sparkle accepts an update whose app is renamed if the **bundle ID is the
  same**. It keeps the **old folder name** on disk. With a changed ID it works
  only if the zip contains an app with the **old filename**. (Local rehearsal.)
- In this app, Sparkle starts only when the Settings or Updates window opens
  (`SelfUpdater.controller` is a lazy static), so automatic self-update checks
  don't run until then. This is a bug to fix (phase 8).
- `brew install --cask --adopt` adopts only artifacts **identical** to the cask's
  download, and cannot be combined with `--force`. Of 7,814 casks, 656 use a
  `pkg`, and 2,050 are marked `auto_updates`. Microsoft Word is a pkg cask.
- Discover endpoints that responded: `formulae.brew.sh` (cask 2.1 MB, formula
  5.2 MB over the wire), npm search, crates.io (needs a User-Agent), RubyGems.
- 1.8.0 weighs 7.9 MB on disk, 30 MB resident after 11 hours, 0.1% CPU idle,
  and keeps a 19 MB `cask-index.json`.

**Not verified. Test before relying on it:**
- Whether `sudo -A -v` primes a cache that later `sudo` calls in the same batch
  reuse when there is no terminal (phase 3).
- What `brew install --cask --force` does to an existing app.
- Whether the "Replace" adoption flow (Trash, then install) works end to end.
- Whether PyPI has any usable search. Assume **no**.
- Whether the editor-extension marketplace APIs are usable.
- Where macOS 27 puts the sidebar toggle, and whether the standard sidebar
  already renders edge to edge.
- Whether `raw.githubusercontent.com` URLs follow a repo rename.
- Dark-mode appearance of the mockup (only light mode was viewed).

**Review findings: things the plan didn't cover. Handle them in the phase named.**

1. **`release.sh` pushes `main` by name** (`git push origin main --tags`). Run
   on `release/2.0.0`, it commits the appcast to the branch, pushes the tag and
   an unchanged `main`, and creates the GitHub release, so the live appcast
   never lists the release. Before any 2.0 release, it must run on `main` after
   a merge, or refuse to run off `main`. Fix in phase 5 with the variables work.
   Don't run it.
2. **No beta-channel path exists yet. Fix before the first beta (phase 5).** `release.sh` can't tag an item
   `sparkle:channel` beta, and `SelfUpdaterDelegate` has no
   `allowedChannels(for:)`, so a beta build wouldn't see the next beta. An
   untagged beta item would go to **every** 1.8 user. The fix: `release.sh` takes
   an optional channel and writes `<sparkle:channel>beta</sparkle:channel>`.
   `SelfUpdaterDelegate.allowedChannels(for:)` returns `["beta"]` when the
   running version has a prerelease marker (`VersionParts.track > 0`), else an
   empty set. Verified: Sparkle 2.9.4 has `allowedChannelsForUpdater:`. Also make
   `release.sh` refuse to run unless the current branch is `main` (item 1).
3. **The sudo cache is keyed by parent process when there's no terminal.**
   The `sudoers` man page on this Mac (sudo 1.9.17p2) says the `tty` and `ppid`
   timestamp types fall back to the parent PID with no terminal. So a priming
   `sudo -A -v` from the app should cover the app's **own** `sudo` calls
   (`runPrivileged`: mas, Sparkle bundle swaps, kext removal), but almost
   certainly **not** `sudo` calls Homebrew makes for pkg casks. Phase 3 still
   tests it. Changing sudoers (`timestamp_type=global`) is a system security
   setting and is **out of bounds**.
4. **Parallel lanes can open two password dialogs at once.** Each `sudo` call
   spawns its own askpass dialog. Until the broker exists, never let two lanes
   run something that may need admin at the same time.
5. **The Homebrew lane is keyed by tool, not by source.** `caskOracle` and
   `components` install with `brew install --cask --force`, and these also call
   `brew`: `HomebrewSource.detect` (`brew update` on every Check Now, including
   one clicked during an install), `DependencyManager` (`brew install mas`),
   Discover installs and adoption. Every `brew` mutation goes through the one
   Homebrew lane.
6. **Homebrew downloads in parallel already (verified).** Homebrew 7.0.11
   downloads in parallel inside **one** command, set by
   `HOMEBREW_DOWNLOAD_CONCURRENCY` (default `auto`, twice the CPU cores). So
   the Homebrew lane runs one `brew fetch` for every queued formula and cask
   first, then the `brew upgrade` / `install` steps one at a time, each with its
   own progress and Cancel. Never run two `brew` processes at once. Not yet
   verified: that each upgrade reuses the fetched download with no second
   download. Check that in phase 3.
7. **Icon fallback changes slightly.** 1.8.0 shows the *source symbol* tile
   when there's no app icon (`AppIconView` in `Cards.swift`, with `IconCache`
   already caching real icons). 2.0 shows the first letter for app-type items
   and the section icon for packages. macOS update rows keep the Apple logo.
8. **Leftover "UpdateScout" names that Part 1 must change:** the self-update
   row is named after the bundle folder, so it reads "UpdateScout" after the
   Sparkle hop (name it from the bundle's display name instead). Also the
   `"Opens UpdateScout's own updater."` caveat in `SparkleSource`, the
   hard-coded fallback path in `Askpass.path`, `build-app.sh --install`, and the
   askpass dialog's default text.
9. **A test target works (verified in a scratch copy).** Adding
   `.testTarget(name: "UpdateScoutTests", dependencies: ["UpdateScout"], path:
   "Tests/UpdateScoutTests")` and a Swift Testing file with
   `@testable import UpdateScout` builds, and `swift test` passes. Sparkle
   loads fine. No library split is needed.
10. **Sparkle lazy start is confirmed in code.** `SelfUpdater.controller` is a
    `static let`, touched only from Settings and the Updates window. Phase 8 fix
    as planned.
11. **Menu bar glyph: settled.** It becomes the prism (see the decisions table

12. **New-source commands, verified on this Mac (29 Oct 2026).** Nick asked
    for the tools to be installed. Homebrew now has `pipx` 1.18.7, `uv` 0.13.6,
    `rust` (cargo 1.99.1) and the `visual-studio-code` cask (1.144). `npm`
    10.9.9 and node came from Homebrew already. For each source, an outdated test
    package was installed, detected, upgraded and re-checked:
    - **pipx:** there is no "outdated" command. Read installed versions from
      `pipx list --json` (`venvs.<name>.metadata.main_package.package_version`)
      and the latest from `https://pypi.org/pypi/<name>/json` (`info.version`).
      `pipx upgrade <name>` works. Respect `pipx pin`.
    - **uv tools:** `uv tool list --outdated` works but is **text only** (no
      JSON in 0.13.6): `ruff v0.5.0 [latest: 0.17.3]`. **Gotcha:** a tool
      installed with an exact version is pinned. `uv tool upgrade` leaves it
      alone and prints a hint, yet the outdated list still shows it. Show such
      tools as "Pinned". Moving one takes `uv tool install <tool>@latest`, which
      worked, but only on an explicit click. uv tools live in `~/.local/bin`,
      which isn't on PATH. Don't depend on it.
    - **npm global:** `npm outdated -g --json` **exits 1 whenever anything is
      outdated**. Treat valid JSON on stdout as success. The list includes
      `npm` itself, which belongs to Homebrew's node. Skip `npm` and `corepack`
      (or say "updated by Homebrew"). `npm install -g <pkg>@latest` works.
    - **VS Code extensions:** `code --list-extensions --show-versions` lists
      them, and `code --install-extension <id> --force` updated one (there is
      also `code --update-extensions`). The latest versions and search come from
      the Marketplace `extensionquery` endpoint, which works without a login.
      It's an undocumented preview API, and Microsoft's Marketplace terms limit
      Marketplace use to Microsoft's in-scope products. **Nick's decision
      (29 Oct 2026): use both.** Use the Marketplace for VS Code extensions and
      Open VSX for Cursor and VSCodium. If the Marketplace call fails, show that
      source's own error and fall back to Open VSX for the version, without
      breaking the other sources. Open VSX (`open-vsx.org/api/<publisher>/<name>`,
      `/api/-/search?query=`) is open and also works. It suits Cursor and
      VSCodium (Cursor isn't installed).
    - **PyPI:** search is **confirmed unavailable** (XML-RPC `search` returns
      "PyPI no longer supports 'pip search'"). Exact-name JSON works. Ship the
      curated list plus exact lookup, as planned.
    - **pip --user:** python.org Python 3.11's `pip3 list --user --outdated
      --format=json` works (nothing there today). Homebrew's Python 3.15 is
      externally managed (PEP 668), so never install into it.
    - **cargo:** installed for Discover's crate installs. `cargo install --list`
      is empty.
    - **Test packages left installed (all now up to date):** pipx `cowsay`, uv
      `ruff`, npm global `cowsay`, and the VS Code extension
      `esbenp.prettier-vscode`. To make outdated items again, install an old
      version: `pipx install "cowsay==5.0" --force`,
      `uv tool install "ruff==0.5.0"`, `npm i -g cowsay@1.5.0`,
      `code --install-extension esbenp.prettier-vscode@10.1.0 --force`.

**Concurrency setting:** Settings, group "Updating", a stepper 1 to 8, default 4.

**Lanes:** downloads in parallel. Installs run **one at a time per manager**
(one `brew`, one `npm`, one pip environment), because Homebrew holds locks.
Sparkle apps and the App Store can run alongside Homebrew.

**Install queue (phase 1):** replace the single `cancelRequested` flag, the
shared `"install"` process tag, and the `"Queued…"` string with an **install
state enum** (queued, downloading with progress, installing, needsAdmin, failed
with message, done) and a **Task and process tag per item** so cancelling one
item doesn't stop the others.

**One password per batch.** The vision doc proposed an elevated batch script.
**That doesn't work for Homebrew:** Homebrew refuses to run as root, and pkg
casks call `sudo` themselves. 1.8.0 handles this with `SUDO_ASKPASS` pointing
at a helper (`UpdateScout --askpass`, see `Shell.swift` and `AskpassDialog.swift`)
that shows a dialog **per `sudo` call** and stores nothing. So "Update all" can
prompt several times. Do this, in order:

1. **Test first (phase 3):** does one `sudo -A -v` at the start of a batch
   prime a cache that the later `sudo` calls reuse, given there is no terminal?
   Try it on the real Homebrew pkg-cask path. Report the result to Nick.
2. **If yes:** one prompt at batch start (the popup sheet in 4.7), then run.
3. **If no:** ask Nick before choosing. The likely design is a broker inside the
   app: it asks once, keeps the password **in memory only** for the batch, and
   serves it to the askpass helper over a private per-batch Unix socket
   (directory mode 0700, one-time token), then wipes it. That needs Nick's OK.
   The proper long-term fix is a privileged helper (`SMAppService` + XPC), which
   needs signing work and **is not part of this build**.

Always: never store or log the password, never write it to disk, never put it on
a command line, and let the system's own Touch ID dialog work if it is used.
Mark items that will need admin (pkg casks) **before** they run.

## 6. Things that bite (from CLAUDE.md, plus what we found)

- **Two processes write `state.json`:** the app and the headless
  `--background-check` agent. **Always** use `Store.mutate`, which locks,
  re-reads and applies only the change. Never save a stale in-memory copy. New
  state fields must decode with defaults.
- **`MenuBarExtra` labels are flattened to an image.** View modifiers and
  SwiftUI animations are dropped. Animate with pre-drawn template frames
  (`Views/MenuBarIcon.swift`). Keep a **single** status item so Thaw, Ice and
  Bartender keep its position. Re-check with Thaw whenever the label changes.
- **Sparkle release tracks** come from the installed version (`VersionParts` in
  `Models.swift`, `AppcastParser` in `Sources/SparkleSource.swift`). Some feeds
  leave betas untagged, so version markers count too.
- **Item ids include the install token.** Don't change the format.
- **Liquid Glass:** `build-app.sh` patches the linked-SDK version so AppKit uses
  the new UI. Use the style helpers.
- **Homebrew locks:** never run two `brew` mutations at once.
- **Sparkle lazy start** (3.3): fix in phase 8, not before.
- **Custom sources run shell commands on every check**, including headless
  background checks (a known leftover, phase 8).
- **The installed 1.8.0 erases 2.0's new state fields while testing.** Its
  background agent (every 5 minutes on Nick's Mac) decodes `state.json` with the
  1.8.0 struct and writes it back, dropping `activity`, `ignoredApps` and
  `ignoredMajors`, and the pip and npm items until the next 2.0 check. Only a
  test-build problem: after the upgrade the agent runs 2.0.
- **The status item is an `NSStatusItem`** (`StatusItemController` in
  `Views/MenuBarIcon.swift`), not a `MenuBarExtra`, so left and right clicks
  can differ. Keep its `autosaveName`; Thaw may lose the old position once.
- **Test builds share the bundle ID and data folder with the installed app.**
  See section 8.

## 8. Testing safely

- **Build:** `scripts/build-app.sh` writes `build/PrismPack.app` (the
  executable inside is still `UpdateScout`). `swift build` is the quick
  compile check. `--install` copies to `/Applications`, which replaces Nick's
  installed copy: **don't, unless he asks.**
- **Quit the installed copy before running a test build.** Both share the bundle
  ID and `~/Library/Application Support/UpdateScout/`. Ask Nick to quit it.
- **Never toggle "Check for updates in the background" in a test build.** It
  points the real launchd agent at that build.
- **Background check by hand:**
  `<app>/Contents/MacOS/<exe> --background-check`.
- **Testing Sparkle self-update:** use a **throwaway** key pair, a localhost
  appcast served with `python3 -m http.server`, and a **different bundle ID**
  for scratch builds, as in the rehearsal. **Never touch the real signing key.**
  Note that `HOME=` overrides do **not** isolate the preferences domain, and that
  Sparkle only starts when a window opens unless you start it yourself (in a
  scratch copy only).
- Test the 12 adoption cases and the parity checklist. Report what you ran, what
  passed and failed, and what you couldn't test.
- A browser pane may not paint if its window is minimised. If you can't see a
  page, say so rather than claiming it looks right.

- A privileged helper (`SMAppService` + XPC).

  frameworks, Go tools. (Later, if Nick asks.)

- A new app icon, or edits to the real signing key or `SUPublicEDKey`.
- Telemetry, accounts, or any network call not listed here.
- Removing or hiding any 1.8.0 section or feature.
- App Store apps or macOS updates in Discover.
